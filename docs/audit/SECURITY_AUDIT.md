# Security audit

**Scope:** source/config/schema review of feature worktree commit `7165fa130e413f8dc8893b85d30ecbe530ef8173`. No live Firebase, database, cloud, or external service was contacted. This is not an ASVS certification or penetration test.

## Strengths present in source

- `packages/api-contracts/classync_contracts/token_verification.py` validates Firebase project/audience/issuer/subject, email verification, disabled/revoked state and fails closed; emulator mode is not accepted as institutional identity.
- `request_authorization.py` requires a verified principal plus fresh server membership in configured tenant, selected role grant and required record link. Route guards are treated as UX, not authority.
- `packages/persistence/classync_persistence/migrations/versions/0001_identity.py` through `0016_announcements.py` provide scoped relational identities/resources, revisions, FK/check constraints, FORCE RLS and audited/immutable publication structures. Inspect exact upgrade graph/privileges on disposable PostgreSQL before deployment.
- `services/gateway/app/main.py` applies exact-origin CORS policy and generic request error boundaries; verify all deployments use the intended settings.
- `infrastructure/firebase/firestore.rules` is deny-by-default. This does not authorize Firestore use or prove deployed project rules.
- Registration processing has size/time/resource boundaries and owner/tenant-scoped access in `services/gateway/app/registration*.py`; fresh current-candidate edge tests are still required.

## Injection and privacy boundaries

Pydantic `extra="forbid"`, Literal/Enum, UUID and anchored IDs should constrain shape and reject unknown fields. They do not make arbitrary values “injection-proof.” Use SQLAlchemy bound parameters; never concatenate user input into SQL, shell, file paths, model prompts, or HTML. Use React text rendering, strict upload parsing, output encoding, authorization checks, CSP and negative tests. Do not put personal data in URLs, logs, telemetry, AI prompts, or exception bodies. External LLM suggestions must be inert until a human selects and the deterministic validator accepts the resulting structured change.
