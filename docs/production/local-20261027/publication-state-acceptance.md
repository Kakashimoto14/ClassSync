# P3b PostgreSQL publication state foundation — before implementation

28 October 2026. Entry: shared publication rules/workload correction locally PASS, backend650/security16; original hashes preserved. Owner's local P2–P8 source/test/disposable-data authority applies. Full P3b remains partial and PostgreSQL publication stays unavailable at the HTTP/provider boundary.

This slice introduces only the relational persistence foundation for existing publication state. It neither grants institutional publishing authority nor implements P6 approval/P7 publication acceptance.

- Explicit migration0007 follows0006 and creates immutable publication versions plus revision heads in classsync_scheduling. No service-start migration or original database connection. Caller-owned upgrade failure rolls back; disposable downgrade removes only this slice and upgrade restores it. Downgrade is destructive for these disposable tables, not a data-preserving rollback claim.
- Versions retain tenant/dataset/period, verified actor/owner and owned immutable draft FK, academic revision, positive publication revision, server sequence/ID/time, original save key, exact canonical command/request hash and publication payload/checksum. Constrain JSON metadata to the relational envelope; command calendar and stored calendar agree. Unique tenant/dataset/key and tenant/dataset/period/revision prevent duplicate state. No generic SQL compatibility bridge.
- A head references an existing same-tenant/dataset/period/version revision. Initial head is revision1; later updates advance exactly one revision and cannot retarget their scope. Version UPDATE/DELETE/TRUNCATE and head DELETE/TRUNCATE fail. No stale/missing-version/foreign-owner binding or partial transaction may become visible.
- A deferred constraint requires each inserted version to have its own same-owner head at commit. Insert-version then advance-head may occur within one transaction; committing a version alone fails. Test the deferred check explicitly without leaving a successful orphan probe behind.
- Preserve the existing private academic owner boundary even when two active Administrators have distinct academic rows with the same period ID. Head ownership is stable; another owner cannot insert a succeeding version into that scope, advance its head or retarget its owner. No shared institutional editing permission is inferred from the Administrator role.
- ENABLE/FORCE RLS and no PUBLIC privileges on every new table/function. Current active Administrator plus exact server project/tenant required. Read access is to published state only; writes bind version owner/actor to current verified UID. Head writes can reference only a version authored by that current owner. No Student/Teacher projection is enabled by this foundation; wrong roles/UID/tenant/project and revoked memberships fail or see no rows. Non-superuser table owners cannot bypass RLS; pooled context clears.
- Before application adapter adoption, run a guarded new-cluster actual PG qualification with generated owned academic metadata, an actual independently validated CP-SAT draft, exact command/payload/hash/metadata retrieval across a physical reconnect, raw constraint/immutable-DML/head transition probes, rollback and two active Admin owners/current membership negatives. Fresh source/original preservation and stopped-cluster evidence required. Independent source/evidence review, portable safeguards, relevant/full backend/Ruff/package checks precede acceptance.
- Schema integrity alone does not prove academic readiness/hash freshness, approval, conflict-safe publish, concurrency, outbox/realtime, migration of old publication history, backup/restore or full P3b. Those remain explicit adapter/provider and later phase gates; keep all institutional PG publication endpoints unavailable until qualified. No new browser/UI/manual accessibility acceptance follows from this backend-only slice.
