# P3a frontend identity/session lifecycle - before implementation

Scope: provider-agnostic Firebase identity observation and current Gateway /auth/me membership. No institutional sign-in/provisioning method, real credentials/settings or sample connected workspace is invented. Existing immutable presentation/sandbox boundaries and Soft Rouge are preserved. Institutional data workflows remain unavailable until qualified. Browser plugin/skill absent; bundled Playwright fallback will be used and recorded.

Acceptance:
- Only compiled institutional mode can start this observer/identity request boundary; presentation and sandbox never observe university session or send /auth/me requests through it. Existing data API gates remain unchanged. Missing Firebase configuration remains unavailable, no demo fallback or credential submission.
- Observe Firebase onIdTokenChanged, get an SDK token without decoding token roles, GET current /auth/me; role candidates are verified via server X-ClassSync-Role, not granted in browser. Validate response UID/tenant/knownrole/revision/requiredrecord contract. Never application-store/log tokens, grants or credentials.
- Clear prior membership before every verification, identity change, signout, denial, offline/unavailable or timeout. Abort obsolete fetches, generation-guard late SDK/token/response completion, unsubscribe on unmount/StrictMode. Never revive old user/role after signout/disposal; logout failure keeps access cleared until successful logout. React renders typed status and accessible retry/role selection/signout controls; no sample dashboard for authenticated identities.
- Test happy single/multi-role and malformed/wrongUID/servererror responses, tokenfailure, missingidentity,401/403/503/nonJSON/offline/timeout, identityswitch/request races, selectedrole/revocation, signout failure/late completion and cleanup. Render status using actual existing UI primitives; verify keyboard/mobile/desktop and negative states. Real emulator+currentPG+Gateway+browser lifecycle proof is required before full slice PASS; test doubles alone are insufficient. OriginalDB hashes preserved; independent review and relevant fullgates before phase advancement.
