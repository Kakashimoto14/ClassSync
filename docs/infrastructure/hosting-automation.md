# Connected hosting review

Use the feature worktree as the source. The repository root `vercel.json` still builds the read-only presentation. The connected application uses a separate Vercel project and generated configuration. No hosting file in this workflow applies a provider change.

For local evaluation, run `npm run dev:connected` from the feature worktree. See [local connected development](local-connected-development.md) for the printed URLs, test accounts and shutdown. Local emulator settings are rejected by the Cloud Run startup guard and are not part of the connected Vercel build.

## Generate the review bundle

From the installed Python environment, run `python scripts/hosting_plan.py --inventory` for environment names and `python scripts/hosting_plan.py --schema` for the non-secret selection schema. The tracked root, service and web `.env.example` files document the service scopes. A reviewed selection belongs under ignored `var/hosting`. Then run:

```text
python scripts/hosting_plan.py --metadata <reviewed-selection.json> --output var/hosting/<new-review-directory>
```

For existing resources, `--refresh-provider-values --firebase-app-id <approved-web-app-id>` reads the client-safe Firebase Web SDK fields and the Cloud Run origins and runtime identities using authenticated Firebase CLI and gcloud. It keeps the explicitly reviewed image digests. It does not read deployed environment values, passwords, token contents or secret versions. No owner copying of Web SDK fields is required. A new target has no service URLs to discover until approved creation; do not put invented URLs in its selection. The optional lookup has fixture coverage and has not run against real providers.

Output: `vercel.connected.json`, `vercel.variables.json`, `cloudrun.academic.json`, `cloudrun.scheduling.json`, `cloudrun.gateway.json`, and `review.json`. The Cloud Run files use digest-pinned images, separate runtime identities and pinned Secret Manager references. The Vercel file uses the institutional build and a same-origin Gateway rewrite. The variable manifest scopes values to Preview or Production; only client-safe values belong there. `review.json` records that deployment is not authorized. Keep provider outputs and account-specific metadata out of Git.
