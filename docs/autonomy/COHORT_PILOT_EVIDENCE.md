## Implemented

- Read-only application curriculum catalog for ICS/IBE/ITE: **39 source identities, 8 programs, 2,062 unreviewed rows, 20 distinct PDF hashes**. Preserve archive member, source PDF/hash/page/row, printed curriculum AY, exact code/title, prerequisites, Lec/Lab/Units, cohort-folder label and Puray variant. Content-derived course IDs survive row reordering; identical PDFs do not merge cohort applicability. TCP has no supplied prospectus.
- `AcademicSubject` references an immutable source version/course and has separate curriculum-review/contact-minute verification. Bound courses receive **no implicit 180-minute default or patterns**. Exact code/title/program/year/semester matching is checked server-side; source identity cannot be rewritten after saving. Unique record labels and a PostgreSQL source-course index allow same codes in different versions.
- `AcademicSection` separates entry cohort and assigned version from current year. Binding must match the explicit program/cohort source; existing binding cannot automatically change. Frontend derives `BSIT3A` from program/year/letter without replacing stable internal record IDs. No active real sections are inferred from the kit.
- Enrollment can carry its explicitly assigned cohort/version. A new PostgreSQL **immutable `classsync_academic.cohort_bindings` registry** retains bindings across enrollment removal and new periods. Keys follow existing tenant/owner academic isolation; it does not create people, identity memberships or accounts. No implicit student equivalency/migration workflow is introduced. Transfers/irregular or mixed-curriculum exceptions require separately approved mapping; cross-owner institutional Registrar coordination remains a real-import prerequisite.
- Administrator subject/section forms load institute-filtered curriculum sources, expose printed evidence, select exact courses, save incomplete source-review records, and show verification controls. Existing offering/faculty/resource/constraints/calendar entry remains. Curriculum blockers have a dedicated readiness group and source-review links. Connected period/catalog/calendar/readiness/generation/draft/validation requests use existing protected endpoints and token headers; synthetic fixture import is hidden in institutional mode.
- Synthetic candidates are explicitly tagged; their provenance cannot be removed through record updates, and they cannot carry an institutional HR ID. Institutional readiness, raw scheduling validation and publication reject tagged candidates. Existing application demo factories also tag their candidates. Provisional/unavailable rooms remain subject to existing eligibility checks.
- `cohort_pilot.py` constructs **27 hypothetical first-term BSIT offerings (8/8/8/3 across Years1–4)**, 81 candidates (three eligible options per exact code), four mock rooms and explicit enrollment bindings. Its 180-minute/two-90 patterns, capacities, availability and calendar are **test assumptions independent of printed hours**. No green timetable session becomes an approved lock.
- PostgreSQL synthetic seeding is atomic through the existing academic repository, revision/reference/checksum/audit/RLS path. No new datastore/service, identity system or scheduling engine. Migration `0012_curriculum_identity` adds only the source-course index and immutable binding registry with FORCE RLS; existing payloads are not rewritten. Runtime needs only SELECT/INSERT on the new registry, never UPDATE/DELETE. Only a disposable cluster was migrated. Any future migration/downgrade of original data needs separate approval, backup and preservation of binding history.
- Optional DTO fields preserve historical scheduling hashes when absent/default; true synthetic markers and explicit enrollment bindings are hash-bound. Generated TypeScript/schema files were regenerated from Pydantic.
